Capstone Project

MEDDIC Discovery Tool

An AI discovery assistant that turns a call transcript into structured MEDDIC notes, a recommended demo, and competitive context, so SEs spend less time writing up calls and more time preparing for the next one.

▶

Demo video coming soon

The Problem

Discovery notes are a grind, but they shouldn't be.

After a discovery call, SEs often spend time they don't have reconstructing what was said into MEDDIC signals and capturing what mattered so the deal can move forward.

That work is the cost of discovery, not the value of it. The value is understanding a customer's problem well enough to demo the right thing in a tailored, impactful way. This tool handles the reconstruction and goes a step further: it recommends what to demo and how to position against competitors, so the time saved goes straight into preparation.

The Build

12 weeks. A self-designed syllabus. One working tool.

I built this over 12 weeks using a curriculum I designed myself, starting from first principles and working up to a deployable Flask application.

I started with Python fundamentals and data handling with SQL, then moved into how LLMs work and how to direct them with system prompts.

From there I configured the API integration using the Anthropic API, vector storage with ChromaDB to store past deals as historical context, and finally Flask to wrap it all into something usable.

The MEDDIC Discovery Tool is what came out the other side, and I’m pretty proud of it. You run a discovery call, feed the conversation in, and the tool structures the output against the MEDDIC framework: Metrics, Economic Buyer, Decision Criteria, Decision Process, Identify Pain, Champion. That’s followed by a demo prescription and competitive context for differentiating the product.

It's a Flask application built on the Anthropic API, with system prompts that direct the analysis and ChromaDB storing past deals so the tool can pull from historical context to make the prescription more relevant.

After I demoed the tool to the head of healthcare solutions at Zoom, he said he'd want his SEs to challenge the recommendation and make it their own. That's what I’d suggest for implementation: a chat layer, scoped to the team's workflow, where SEs can challenge and refine the output until it's theirs.

Tech Stack

What it's built with

Python Core language and application logic
Flask Web framework to serve the tool as an app
Anthropic API LLM backbone for discovery analysis
System Prompts Structured instructions to direct model output
ChromaDB Vector storage of past deals for historical context
SQL Data querying and structured storage
